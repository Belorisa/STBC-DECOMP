# x87 and float copies

Operand order on the FPU stack, and whether a float is copied through the FPU or with integer moves. A wall reported
as `register` with FPU instructions in the diff starts here; the order to check things in is [triage.md](triage.md).
Read `README.md` for how entries are written.

## x87 operand order

### x87 operand order: compares

- **x87 compares follow operand evaluation order, left operand first.** `distance < speed * 60.0f` gives `fcompp; test
  ah, 0x41` with no fxch where `speed * 60.0f > distance` adds an fxch (OptimizedFireScript::CheckGoodShot);
  `weights[i] > threshold` gives `fld weight; fcomp threshold; test ah, 0x41`, the reversed operands `test ah, 1`
  (MetaVolumePolygonizer); `ratio < Call()` reproduces retail's spilled `fcomp [slot]` where `Call() > ratio` doesn't
  (ShipClass::DamageSystem, MATCH-PENDING on GetCondition's invented level); retail evaluating the listed element
  first is `other.SqrLength() >= ship.SqrLength()` (SetClass::Unknown413CB0 *(open)*); swapping the operands of a
  float `==` changes the `fld` order (ShipClass::WeaponHitHandler). Two float compares in a row ( `fcompp; test 1`
  then `test 0x41`) are an inline three-way compare through accessors, operands in the same order in both tests
  (KeyArray::Compare). {asm: fcompp; fnstsw; test ah, 0x41}
- **`fcomp st(1)` then `fstp st(0)` where this build has `fcompp`, with retail computing a product before an
  unrelated test,** is a named float declared before that test: `float otherVolume = ...; bool otherSplit = ...;
  if ( volume < otherVolume && otherSplit )` (OBBNode::VirtualSlot05; the same local declared after the bool changed
  nothing).

### x87 operand order: sums, products and vectors

- **Which operand VC6 loads first** (scratch compiles): for globals and `extern` floats, the right operand of each `*`
  and `+` in textual order, whatever their declaration order; for locals, the later-declared local; for parameters,
  the earlier parameter whatever the textual order; a local before a parameter. So a swapped operand pair between two
  locals is their declaration order, and between two globals the expression's own order.

- **NiPoint3 operator order: the right operand is evaluated first.** VC6 evaluates the right operand of `+` and `*`
  first in member-call chains: swap operands to fix the call order (PhaserBank::GetArcPosition, `rotation * position +
  location`); a member `operator+` evaluates its argument before the object, so retail's first-computed term is the
  right-hand operand (PhaserGraphic::Unknown4E7200 *(open)*). `R * ( s * p ) + T` loads T first, `T + R * ...` loads R
  first (PointsToWorldSpace); corner sums `reach * m1 * m2 + origin` give retail's `fld result; fadd origin` where
  `origin + ...` flips it, and where retail copies the position up front, a local `NiPoint3 origin = position;`
  (PhaserProperty fan builder *(open)*). In long NiPoint3 chains, read operand order from the expression's out-of-line
  copy in the other branch (ecx and push order show which operand is `this`): `V(3) + 3.0f * V(6)` computes the product
  before loading V(3) (NiBezierTriangle3::Unknown83BFB0). `a.Dot( b )` and `b.Dot( a )` pair the fmuls differently, and
  `GetOrientationForward().Dot( offset )`, the returned point as `this`, gives retail's z-first `fld [esp]; fmul
  [eax+8]` where `offset.Dot( ... )` does not (TractorBeamProjector::IsInArc).
- **`a * s + b * t` left first:** `NiColorA from = a * s; NiColorA to = b * t; return from + to;` gives retail's
  left-first x87 order where the one-line form evaluates the right operand first (NiLinColorKey::Interpolate).
  Argument evaluation order sets it too: `t * key1->pos + ( 1.0f - t ) * key0->pos` (NiLinPosKey::Interpolate) and a
  member-init list in declaration order ( `: time( time_ ), pos( pos_ )`) fix operand order on the FPU.
- **Inside an inlined compound operator (`r += c.r`) the order of first reference sets the operand order for every
  caller alike.** When retail's callers differ with the same loop text, the header can't separate them and the
  deciding input is in each function (its initialiser: member against friend product). NiColorA's `operator+=` is the
  1.1.2 text; `r = c.r + r` makes NiBezierPatchEvaluate's 0x851620/0x852CD0/0x853870 exact and breaks the matched
  twins 0x851840/0x852F00, so it is not taken.
- **A product in another x87 order is its parenthesisation:** when reordering `a * b * c` won't move it, write `c * (
  a * b )` (AtmosphereShockWave::Fill). VC6 moves a literal multiply last in `a * LITERAL * b`; retail multiplying by
  the literal second is `( a * LITERAL ) * b` (PhaserGlow::VirtualSlot35), and a constant retail multiplies first
  (`fild; fmul const; fmul member`) needs the parentheses written: `( ( i - 20 ) * RING_SPACING ) * fieldRadius`
  (AsteroidFieldPlacement::CreateFieldModel *(open)*). `a * b * dt` with a getter product first gives `fld; fld; fmul
  st(1)` and a later `fstp st(0)` (RepairSubsystem::Update, MATCH-PENDING on GetCondition's invented level).
- **Sums of squares.** VC6 loads the last term of a sum of squares first: write `a.w*a.w + a.x*a.x + a.y*a.y + a.z*a.z`
  in member order to get retail's z, y, x, w loads (TGAnimationEntry::Nearer). A squared length spelt `v * v`
  (NiPoint3's dot operator) loads z, y, x; `SqrLength()` on a local loads y first: check retail's first `fld`
  (IdealControlledCameraMode::Unknown421410 *(open)*). Didn't help in: SphereDistanceModifier::ModifyDistance (the
  no-hit branch's squared lengths open-coded in member order). Three scalar squares that load z, x, y in this build
  where retail loads z, y, x, with every term order giving the same, are the sum grouped `x * x + ( y * y + z * z )`
  (FlareController::EmitFlare: MATCH).
- **Square roots.** A square root stored straight to its destination (where `Length()` gives `fstp st(3)`, a pop, then a
  store) is an open-coded `(float)sqrt( x * x + y * y + z * z )`, TG's own spelling (NetworkAI's constructor, TGStream);
  `(float)sqrt( v.SqrLength() )` also stores straight off `fsqrt` where `v.Length()` pops first
  (ShipClass::VirtualSlot84). `sqrtf( v.SqrLength() )` gives x*x + y*y + z*z in that order on a vector whose y and z are
  still on the FPU stack, where `v.Length()` starts with y*y (SpecularPass::Display's halfway vector). A sqrt result
  that retail stores to a frame slot and pushes through a register is `(float)sqrt( ... )` into a local, not `sqrtf`
  (AsteroidFieldPlacement::CreateFieldModel *(open)*). Didn't help in: SetClass::GetDistance (`(float)sqrt` fixed the
  store but reordered the squares; it closed with plain `Length()` once that took the lineage's NiSqrt body),
  NiMatrix3::Reorthogonalize (`float( sqrt( ... ) )`, the 1.1.2 NiSqrt body), SpecularPass::Display (an open-coded
  sqrt). {asm: fsqrt; fstp}
- **`x = x + d` gives `fld x; fadd d`; `x += d` gives `fld d; fadd x`** (TGTimerManager::RebaseTime). Explicit
  parentheses set the sum order where `+=` doesn't: `duration = duration + ( fadeIn + fadeOut )` gives
  `fld fadeIn; fadd fadeOut; fadd duration` (TGCreditAction::Play).
- ** `fld height; fadd top` against this build's `fld top; fadd height` through `this`** is one operand read through
  its inline accessor: `top + GetHeight()` weighs the call side heavier and loads it first (TGRect::IsWithin, ClipTo).
  Swapping the members ( `height + top`) doesn't do it. The order depends on context, so the fix belongs at the
  caller, not in the shared accessor: rewriting `GetBottom` the same way matched these two and pulled every
  `GetBottom` on a stack TGRect away (TGTextButton's frames). Before editing a shared inline, run `build -s` and keep
  the spelling most callers agree with. The lever needs an existing float accessor on one side: two member reads of
  equal weight (the products of `NiPoint3::Dot`, NiOBBox::TestRay), two locals (STTopLevelMenu::MouseHandler) and a
  member plus an argument ( `unknown48 += elapsed`, WeaponSystem::Update) don't move, and there `a = a + b`,
  `a = b + a`, `+=` and a local sum all compile alike. The same weighting reads the other way through a `const NiRect
  &` local: `left + right` through the local loads left first, the inline accessor at each use
  (`camera->GetViewPort().right`) loads right first (ViewScreenNode::ProjectPoint).
- **x87 operand order z, x, y against this build's x, z, y on a member point** can be the accessor (
  `bound.GetCenter()`, `GetRadius()`) where the source read the member (NiBound::TestIntersect;
  NiSwitchNode::UpdateModelBound's `childWorldBound.GetRadius() * oneOverScale`).
- **`x -= pt->GetX()` gives `fld pt.x; fsubr x`;** `x -= pt->x` gives `fld x; fsub pt.x` (TGPoint3::Subtract).
  {asm: fld; fsubr}
- **A NiPoint3 built with the three-float constructor makes later multiplies and adds load its components first,**
  an inlined Unitize included; three member stores load the other operand first (ShieldClass::Unknown56A690).
  The same holds for a Cross result: `NiPoint3 axis = up.Cross( d ); axis.Unitize();` loads x first, while
  `NiPoint3 axis; axis = up.Cross( d );` gives retail's `fld st(0); fmul [x]` (CameraObjectClass::Unknown42A290,
  ZoomCameraObjectClass::Create; it made Unknown42BE90's sum worse).
- **A comparison written `offset.SqrLength() < radius * radius`** puts the square of the radius after the sum
  (ShipSubsystem::IsHittableFromLocation).
- **`center /= count` divides in place;** `center = center / count` makes a temporary (NiBox::CreateFromData *(open)*).
- **`v / x` through NiPoint3::operator/ gives `fld x; fdivr 1.0`** when x is a member or a dereference; with a
  by-value float parameter both spellings load 1.0 first (PhysicsObjectClass::Unknown5A1150; PhysicsObjectClass::Unknown5A0D80 *(open)*,
  where `( 1.0f / time ) * ( end - start )` through the friend operator* kept the same `fld 1.0; fdiv`).
- **Componentwise stores straight into the destination** (`v->x = t.x + v->x`, per axis) give retail's
  store-per-axis shape; `*v = a + *v` goes through a temporary (PhysicsObjectClass::Unknown5A09D0, Force::MoveTo).
- **A world-to-model transform** follows VisibleDamage::Unknown4B1940's idiom: name the offset
  `NiPoint3 offset = center - translate;` before `1 / scale` (OBBRoot::Unknown465150; `similar.py` found the twin).
- **Pixel sums declared before the divides, in retail's order** (`bottom = y + height; right = x + width;`), closed
  the schedule of TGIconGroup::SetIconLocation.
- **A negated bound in a stack slot** ( `fchs; fstp [esp]` then `fsub [esp]`) is a named `float lower = -extent[i];`
  with `delta -= lower`; `delta += extent[i]` gives `fadd [mem]` (OBBNode::SphereIntersectsBox). {asm: fchs; fstp}
- **`(float)atan( x )`** gives retail's `fld1; fpatan; fxch; fxch`; plain `atan` or `atan2` don't
  (StarSphere::UpdateTextureScale). {asm: fld1; fpatan}

### x87 operand order: set by the source before the site

The mechanism behind this section is docs/c2-backend.md, "Operand order of commutative operations": the global
optimiser sorts a commutative node's operands by a weight whose low 16 bits hash the operands' symbol numbers, and
those numbers follow first reference in the function's IL (and descriptors an earlier inline freed), so the census
is the numbering. `c2trace --operands` prints the weights and names at each sorted node.

- **The order of two memory operands of one x87 `+`, `*` or `-` is canonicalised, then set by what the function
  named before it.** VC6 ignores the textual order of the operands (`left + right` and `right + left` compile alike)
  and picks the one to `fld` by a key that earlier source moves: in a scratch copy of the unit (`cl /P` of the unit,
  the body swapped, the unit's own flags), storing to one more new member before the site flips the order, a second
  one flips it back, and nothing written after the site moves it. So when one sum of many has retail's operands
  swapped and no spelling of the sum itself moves it, change the census *before* it with a byte-neutral spelling the
  original plausibly had, and check the rest of the function stays put: a chained copy `unknownF4 = unknownDC =
  right;` (NiD3DRender::VirtualSlot41), the lines data named before its vertices `NiLinesData *data =
  lines->GetLinesData(); NiPoint3 *vertices = data->GetVertices();` (PulseWeaponProperty::Unknown68D460 and its twin
  TractorBeamProperty::Unknown697FE0: the same spelling closes both), parentheses around an earlier product's
  reciprocal `( 1.0f / credit->fadeIn ) * ( ... )` (TGCreditAction::Unknown6B2210). A change can flip another site
  as well (a named `start` local fixed TGCreditAction's sum and swapped its `time - start` into `fld; fsubr`): bisect
  by deleting earlier blocks of the body in the scratch copy to find which part decides, then try spellings there.
  The integer `+` sorts the same way, and the chained form is invisible to the debug copy: `u0 = u1 = end;` and
  `u1 = end; u0 = u1;` compile alike at /Od (store u1, reload, store u0), but the chain is first referenced as
  u0, so u0 takes the lower number and the sum `( u1 + u0 )` evaluates u1 into its target as retail
  (NiBezierRectangle::VirtualSlot42 and VirtualSlot49, both /Od-identical to AnimOnly before and after).
  Fake statements that only shift the census are R17; the spelling has to be one the original could have had.
  {asm: fld [a]; fadd [b]}
- **The census is the whole function's IL, and the spellings that move it are the lineage's own.** Same instructions,
  different IL: Gamebryo's NiMath wrappers for the CRT ones ( `NiAbs` for `fabsf`/`(float)fabs`, `NiSqrt` for
  `sqrtf`) applied to the whole function closed NiOBBox::TestRay, FindRayIntersection and NiPosKey::CoordinateFrame,
  where a mix (NiAbs on the extents, fabsf on the tests) did not; a lineage accessor for a member read (
  `reference->GetPhase()`, `GetFrequency()`, added to NiTimeController as NITIMECONTROLLER.INL has them) closed
  NiKeyframeManager::Unknown7A3830's `fsubr`; dropping a local that only renames a member ( `modelData->GetTextures()`
  without `NiGeometryData *data`) fixed NiEnvMappedTriShape::UpdateEnvMapTextures's x, z, y dot; NiPoint3's dot
  operator for a squared length ( `offset * offset` for `offset.SqrLength()`) fixed SphereDistanceModifier's
  squares. Statements AFTER the site count too: `object->GetWorldLocation() + offset` for `offset + ...` (a call's
  operands are not canonicalised) fixed both of NetworkAI::PullTowardPosition's sites, the first inside the earlier
  Unitize; `camera->GetWorldDirection() * toGlow` fixed TractorBeamGlow's base/index order in a later loop. Textual
  swaps of `+`/`*` between scalars, declaration order and local names change nothing (canonicalised or not IL).
- **Try census spellings on a preprocessed copy, not the tree:** `tools/trial.py` compiles hand-written variants of one
  function from the unit's `.i` with its flags (about 0.3 s a variant against 8-30 s for `decomp.py diff`). The user's
  ruling bounds it: one variant first shown to move the output, then at most about 20 hand-written variants per
  function, never a generated product of spellings; an exact variant is a clue that still needs evidence. Macros are
  expanded in the `.i` ( `RAND_MAX` is `0x7fff`), and a header edit can be tried by substituting the class body there
  first. A kept spelling is applied to `src/` and confirmed with `match`.
- **A constant two units share is a literal, not a class static:** EmitterController's `HALF_DEGREE` (0x88CA04) is also
  read by RotateBonesController::SetTarget, whose source writes `( 1.0f / 360.0f )`; spelt as
  that literal, ExplosionPlumeController::SetUpRandomVelocity's angle product loads the variance first as retail does (a
  literal multiplies last, a named static ties on the census). Check `get_xrefs_to` on a constant's address before
  naming it.

### x87 operand order: which local holds a value

- **The identity of a local sets a commutative operand's order.** Retail's `fld step; fadd weight` came from reusing
  the first loop's `time` local, reset, as the second loop's weight; a fresh `weight` local gives the opposite order
  (TGAnimationEntry's three key blenders). Reusing a float for its own reciprocal ( `length = 1.0f / length`) or
  leaving a temporary unnamed (a Cross inside a Dot) fixes operand order (NiBillboardNode::RotateToCamera,
  NiMatrix3::EigenSolveSymmetric); bits worked in place through `unsigned int *rep = (unsigned int *)&length` fix
  ECX/EDX swaps (NiPoint3::UnitizeVectors). *Evidence required:* the pun is Gamebryo's own (NiPoint3.cpp); outside
  lineage code a pointer pun is R4.
- **A repeated difference stays an expression:** naming `elapsed = sample->time - previous->time` made VC6 copy the
  time early; repeating the expression matches (CameraLagTracker::IsRedundant).
- **A named local for an intermediate NiMatrix3 or NiQuaternion** fixes temp-slot sharing and operand order ( `NiMatrix3
  localRotation = ...; SetRotate( GetRotate() * localRotation );`, `NiQuaternion q = ...; q.ToRotation( m );` in
  CameraMode).
- **A re-read game time added to a named static** ( `x + 0.0f`): a named local `float now` gives retail's
  `fadd [mem]` where VC6 would CSE it with an earlier compare (OptimizedAvoidObstacles *(open)*).
- **Fix the control flow before the x87 order:** wrong-order `fadd`s next to a structure difference can be a
  consequence of it (TGRect::Unknown739F00's four corner sums came right with `IsEmpty()` alone).

- **`x + ( 0.0f - y )` keeps `fld y; fchs; faddp`,** where `x - y`, `x + -y` and `-1.0f * y` fold to `fsub [y]`: VC6
  doesn't fold a subtraction from zero (signed zero) (ShipClass::VirtualSlot81, a shield's shortfall below zero).

- **`int / float` divides with `fidivr m32`; `float tmp = (float)i; tmp / f` gives `fild; fdivrp`:** retail's
  fild/fdivrp means a float local or a float-returning step in between (TGUIModule::PixelAlignValue, which
  TGUIObject::Resize needs in that form). `x / float( RAND_MAX )` compiles to the same multiply by the reciprocal as
  `x * ( 1.0f / RAND_MAX )`: a divide by a float constant gives no fdiv, so the bytes can't tell Gamebryo's
  NiUnitRandom from the open-coded form (it is not in NiMath.h: applied tree-wide it loses as often as it wins).
  The fold into `fidivr m32` happens only where the float divisor is on the x87 stack and dies at that divide; a
  divisor in memory gives `fild; fdiv m32` and a divisor still live gives `fild; fdiv st(1)` from either spelling. So
  a function whose axes differ (fild/fdivrp on x, fild/fdiv m32 on y) can be one spelling on both axes: check where
  each divisor lives before reading an asymmetry into the source (TGUIModule::PixelAlignPoint, PixelAlignRect).

## Floats copied through the FPU

VC6 copies a float with integer `mov`s unless the value comes through an inline's float result or parameter in a
way it can't forward. Retail's fld/fstp therefore points at an inline level the source lacks, and retail's integer
moves at one too many.

- **The rule in the compiler** (`docs/c2-backend.md`, "Float copies"; `python tools/c2float.py <addr>` prints each
  copy's tuples and the verdict): every float copy is lowered as `fld src; fstp dst`, and one peephole merges an
  ADJACENT pair into an integer move. The pair stays on the FPU when something sits between the two: the optimiser
  forward-substitutes a single-use intermediate that was set from a non-variable expression (a load through a
  pointer or `this`, arithmetic), which is what a nested inline's return value, a named local copied into another, a
  named local inside an accessor or an inline parameter copied into a local all are; or when an operand has an index
  register: `float a = p[i];` and `arr[i]` keep fld/fstp at one copy level. A one-level accessor gives integer moves
  because the inliner substitutes `return expr;` itself; a static object's member (`g_s.Get2()`) is copy-propagated
  and gives integer moves even at two levels. Under EH the substitution is cut at every EH-state marker anywhere
  after the copy, which is why copies become integer moves into `$T` there. The entries below are the same rule as
  measured from outside.
- **A value stored twice is a named local, not a read-back.** When retail stores a computed float with `fst` and later
  copies it to a second place with integer moves from a spill, the original named the value and stored it twice;
  reading it back through an accessor (`m.SetEntry( 2, 0, m.GetEntry( 0, 1 ) )`) gives `fld [entry]; fstp` instead.
  Store each named value right after computing it (`float xy = ...; m.SetEntry( 0, 1, xy );`): declaring two such
  locals before both stores moves the `fst` later (OBBNode::ComputeCovarianceAndMean: MATCH, its third row set from xy,
  xz, zz; NiOBBNode::ComputeCovarianceAndMean, the lineage copy, reads the entries back and matches that way in its
  own unit). {asm: fst dword; mov eax, dword}
- **The nesting rule:** a float **named local** fed through a **nested inline** (an accessor returning another
  inline's result, often on another object: `TGUIObject::GetWidth()` → `bounds.GetWidth()`,
  `g_kUtopiaModule.GetGameTime()` → `UtopiaApp::GetApp()->GetGameTime()`) is copied with fld/fstp; a one-level
  accessor into a named local gives integer moves, and an **unnamed temporary always gives integer moves**
  (PowerSubsystem::Update closed by calling `UtopiaApp::GetApp()->GetGameTime()` directly;
  TorpedoTube::SendCreateTorpMessage by `GetWorldBound().GetRadius()`; a named `chargeLevel = GetChargeLevel()`, one
  level, kept the integer-move spill in TractorBeamProjector::CanReach). Flags, `const`, `double`, `(float)(double)`
  and `__forceinline` change nothing. `float gameTime = GetGameTime(); x.Update( gameTime );` copies through fld/fstp
  where passing `GetGameTime()` directly gives integer moves (UtopiaModule::VirtualSlot02). The same holds for a float
  spilled across a call: it goes through fld/fstp only as a named local fed by a two-level accessor. In `GetD() >
  GetC()` the front end evaluates the member side first into its own temporary, and that temporary is copied with
  integer moves at any accessor depth; a one-level accessor into a named local (`float c = GetC(); if ( GetD() > c )`)
  gives integer moves too. A named local fed by a two-level accessor (or a `const float &` bound to the accessor's
  value) gives retail's `fld [m]; fstp [slot]` before the call (c2float shows the op 0x162 tuple; `float emptyWidth =
  empty->GetWidth();` before `emptyWidth / iconGroup->GetIconScreenWidth( ... )`, STFillGauge::Layout). So a spill
  needs both the accessor's second level and a caller local: with them (the invented level of the "hidden level" entry
  below) PowerSubsystem::AddPower, ShipSubsystem::IsDisabled, PhaserBank::Update and UpdateCharge,
  PulseWeapon::Update, PoweredSubsystem::Update and TractorBeamProjector::CanReach are exact, MATCH-PENDING. An
  operand spilled across a call through an unnamed temporary stays integer moves however nested, and **with a
  destructor object in scope (an EH frame) even a nested or double copy stays integer moves**
  (EngPowerCtrl::HandlePowerChange *(open)*). One accessor made two-level closes several functions at once
  (TGIconManager::GetScreenWidth/GetScreenHeight closes STFillGauge::RoundToPixels, STMenu::Unknown5260B0 and
  TGParagraph::Unknown732C60), which is the evidence that its original had a second level, though not of its spelling,
  so those stay MATCH-PENDING; look for the member's own type (a rect, a property) before settling on the invented
  level. {asm: fld dword; fstp dword}
- **An inline constructor's float parameter copies a plain float operand through fld/fstp;** retail's integer copy of
  a constant side points at member stores into a named object (`NiFrustum frustum; frustum.left = ...`,
  SpaceCamera::SetDustFrustum).
- **operator+ copies its left operand first:** NiPoint2/NiPoint3's `result = *this` puts x on the FPU and y through a
  stack slot; that copy in retail is `a + b` written as the operator (TriShapeParticles::SetTextureCoordinates).
  Component scales written out by hand where retail passes the scalar through an inline parameter (fld; fst slot) are
  `v *= s`, and `inv = 1/d; v.x *= inv ...` is `v /= d` (ShipClass::StopInSystemWarp, NiGravity::Apply).
- **In a function with an EH frame, VC6 keeps an inline's `$T` and drops the named local it initialises,** so the
  copy is integer moves into `$T` whether or not the destructor object is already constructed (member-only EH
  included), at any flags or VC6 build; only `/GX-` brings the FPU copy back. The one FPU shape left under EH is a
  named local fed by a three-level inline chain and consumed at once (`fstp [esp]`, UtopiaModule::VirtualSlot02).
  Retail's `fld; fstp slot` before a push in EH functions is unexplained *(open)*: UtopiaModule::UpdateWindows,
  Editor::~Editor, MapWindow::Unknown4FEE00, STFileMenu::Refresh, STMenu::MouseHandler,
  EngPowerCtrl::HandlePowerChange; TGParagraph::VirtualSlot92 is exact only through an invented single-use local
  (`float top = rect.top;` before the call, MATCH-PENDING).
- **An inline float wrapper's result named in a local adds an op 0x162 tuple** (the substituted return value): `float
  s = sinf( x );` keeps the tuple, which takes an issue slot after `fsin` and lets an integer instruction pair ahead
  of the `fstp`; `(float)sin( x )` has none (StarSphere::VirtualSlot71).
- **The hidden level under the fpu-copy accessors is a named local, marked `(invented)`** (user's ruling:
  TGIconManager::GetScreenWidth/GetScreenHeight, PowerSubsystem::GetMainBatteryPower,
  PoweredSubsystem::GetPowerPercentageWanted, ImpulseEngineProperty::GetMaxSpeed, ShipSubsystem::GetCondition; by the
  rulings that followed also GetBackupBatteryPower, ShipSubsystem::GetConditionPercentage and GetLastUpdateLength,
  EnergyWeapon::GetChargeLevel): an inner inline, a named local inside the accessor and a template value wrapper are
  identical after the optimiser, so neither the bytes nor the IL can pick one; the functions it makes exact are
  MATCH-PENDING. It fixes a float copied into a single-use local or argument, and a value held across a call once the
  caller reads it into a named local (the nesting rule above); it does not fix a local with several uses
  (ChooseTorpType's `launchSpeed` *(open)*). Under that level, a site retail copies with integer moves reads the member
  directly (StealPower's `fromMain`). A local inside an inline accessor counts toward the unit's declaration count
  (MultiplayerWindow::SelectServerHandler flips with it). ImpulseEngineSubsystem::GetCurMaxSpeed takes the same named
  local (user's ruling): it closes OptimizedFireScript::ConfigureWeaponSystem, MATCH-PENDING.
